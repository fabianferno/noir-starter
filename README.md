# IRL Video Proof ZK Pipeline

This repository contains all zk-specific components for the IRL stereo capture project described in `prd.md`. The goal is to have a fully mocked pipeline that can be exercised end-to-end today, while keeping the interfaces identical to the on-device implementation that will run on the Raspberry Pi.

## Repository Layout

```
/device
  /merkle             # Poseidon leaf + Merkle helpers (Node CLI)
/noir                 # Noir circuit, prover inputs, build script
/verifier             # Off-chain verifier CLI and mock TPM keys
/scripts              # Misc helper scripts (mock signing, etc.)
prd.md                # Full product requirements document
```

## Prerequisites

- Node.js ≥ 18 (Node 20/22/23/25 tested locally)
- Yarn classic (`npm install -g yarn` if needed)
- Noir toolchain (`curl https://noir-lang.org/get` → install `nargo` matching `Nargo.toml` compiler version)
- Barretenberg CLI (`bb`) that matches your Noir release
- OpenSSL (used for mock TPM signing)
- Python 3 (utility scripts use it for portable path resolution)
- `jq`, `xxd`, and standard GNU/BSD coreutils (macOS default works)

## 1. Install JS dependencies

```bash
yarn --cwd device/merkle install
yarn --cwd verifier install
```

## 2. Generate mock capture bundle

This step simulates the Pi pipeline, producing Poseidon leaves, a Merkle root, and Noir witness inputs.

```bash
yarn --cwd device/merkle bundle:mock
# Outputs ./device/merkle/bundle_mock/{bundle.json,Prover.toml,public.json}
```

Flags you may want during testing:

- `--count <n>`: number of synthetic frame records
- `--target-index <i>`: which leaf to expose to Noir
- `--nonce <hex>`: override nonce so it matches an external challenge
- `--out-dir <path>`: write bundle elsewhere (default `bundle_mock`)

The JSON bundle contains both decimal and hex encodings of every field so it can be consumed by Noir, Barretenberg, or on-chain tooling without conversions.

## 3. Compile, prove, and derive verifier artifacts

Use the helper script to run the Noir → Barretenberg workflow. The script optionally regenerates mock data before proving and writes all artifacts to `noir/target/artifacts` by default.

```bash
cd noir
./build_and_prove.sh --generate-mock
```

What the script does:

1. (Optional) Rebuilds the mock bundle via the merkle helper.
2. Runs `nargo check` and `nargo compile` for `real_frame_proof`.
3. Executes the circuit to produce a witness (`bb`-compatible format).
4. Generates a proof and public inputs with `bb prove`.
5. Exports the verifying key via `bb write_vk`.
6. Calls `nargo codegen-verifier` to emit a Solidity verifier contract (`onchain/Verifier.sol`).
7. Runs `bb verify` as an assertion that the proof + VK combination is valid.

All paths can be overridden, e.g. `./build_and_prove.sh --input /tmp/Prover.toml --output ./out`.

## 4. Mock TPM signing flow

Until the Pi TPM integration is wired, use the helper script plus the mock RSA keypair under `verifier/` to sign Merkle roots.

```bash
scripts/mock_sign_root.sh \
  --root-file device/merkle/bundle_mock/bundle.json \
  --key verifier/mock_device_private.pem \
  --out device/merkle/bundle_mock/root.sig.b64
```

This mimics the `tpm2_sign` command described in the PRD. Swap in the real TPM key later; the verifier CLI only needs the PEM-encoded public key.

## 5. Off-chain verification CLI

```bash
node verifier/verify_cli.js \
  --bundle device/merkle/bundle_mock/bundle.json \
  --signature device/merkle/bundle_mock/root.sig.b64 \
  --pubkey verifier/mock_device_public.pem \
  --proof noir/target/artifacts/real_frame_proof.proof \
  --vk noir/target/artifacts/real_frame_proof.vk \
  --public noir/target/artifacts/real_frame_proof.public.json
```

You can skip the SNARK or TPM parts with `--skip-proof` or by omitting `--signature`. The CLI simply shells out to `bb verify` so it stays aligned with upstream tooling.

## 6. On-chain verifier

`./noir/build_and_prove.sh` generates `noir/target/artifacts/onchain/Verifier.sol`. Deploy that contract and pass it the verifying key produced at the same time. The contract ABI matches Noir’s autogenerated verifier template, so you can feed it the proof/public inputs bundle produced earlier.

When rotating circuits or parameters:

1. Regenerate mock bundle (`yarn bundle:mock`).
2. Re-run `./build_and_prove.sh --generate-mock` to rebuild the ACIR, proof, verifying key, and Solidity verifier.
3. Redeploy the new `Verifier.sol` (or upgrade via proxy) and update any backend/off-chain verifiers with the fresh VK.

## Hardware Integration Notes

- The Pi capture service should emit the exact JSON schema produced by `bundle_mock/bundle.json` so it can plug into the existing Noir + proof tooling unchanged.
- Hash-to-field conversion uses BN254’s prime field. Any Pi implementation must use the same mod reduction logic for `frame_hash` and `imu_hash`.
- The current circuit enforces `depth_std_q ≥ 65_000`; adjust `MIN_DEPTH_STD_Q` within `noir/src/main.nr` once you have calibration data. Keep `MERKLE_HEIGHT` consistent across Pi, Noir, and the verifier.

## Next Steps for the Pi

1. Replace the mock frame generator with real captures and IMU samples.
2. Feed the per-frame metadata into `device/merkle/merkle_builder.js` (library mode) or port the Poseidon/Merkle logic to Python/Rust on the device.
3. Use the TPM to sign the Merkle root and drop the signature alongside the bundle.
4. Ship `root_hex`, `root.sig.b64`, `bundle.json`, `proof`, and `public.json` to any verifier (CLI/UI/on-chain).

This setup lets you iterate on circuit constraints, Poseidon parameters, and proof generation off-device today, with a clear bridge to the Raspberry Pi implementation once the hardware is ready.
